# 投稿语录

适用于 AstrBot 的 QQ／NapCat（OneBot v11，`aiocqhttp`）插件。任何用户都可以回复一条消息发送“投稿”，通过“语录”随机回放或“摆酒席”抽取多条。白名单用户可以按 ID 删除指定投稿。基于 [薄暝的 astrbot_quotes_plugin](https://github.com/exynos967/astrbot_quotes_plugin) 适配，版本与复用说明见 [UPSTREAM.md](UPSTREAM.md)。

## 安装

1. 将本目录整体复制到 AstrBot 的 `data/plugins/astrbot_plugin_submit_quotes/`，确保该目录直接包含 `main.py` 和 `metadata.yaml`。
2. 在 **AstrBot 实际运行的 Python 环境**安装依赖：

   ```bash
   python -m pip install -r data/plugins/astrbot_plugin_submit_quotes/requirements.txt
   ```

3. 在 AstrBot 管理页重载插件或重启 AstrBot，启用“投稿语录”。Python 需要 3.10 或以上。
4. 配置并启用 QQ／NapCat 的 `aiocqhttp` 平台。确认目标群聊／私聊在 AstrBot 中允许接收事件，且插件已启用。

文件和视频沿用 AstrBot 的本地文件／回调地址发送方式。AstrBot 与 NapCat 分开运行时，需要 NapCat 可访问相同的文件绝对路径，或正确配置 AstrBot 的 `callback_api_base`；语音格式转换所需的运行依赖沿用 AstrBot。图片和语音通过框架转换为 base64 发送。

## 用法

| 操作 | 输入与结果 |
| --- | --- |
| 投稿 | 回复原消息，发送 `投稿`。整条保存成功后精确回复 `投稿收到了～`。没有引用则提示正确用法。 |
| 随机语录 | 单独发送 `语录`。从所有群聊及私聊的全部投稿中等概率选一条。空库提示先投稿。 |
| 摆酒席 | 单独发送 `摆酒席`。从全局投稿池无放回抽取 6～9 条，以 `第1道菜：<投稿内容>`、`第2道菜：<投稿内容>` 的格式依次发送。 |
| 查看待删除投稿 | 白名单用户发送 `删除投稿`，显示最新一页的完整投稿 ID 和内容预览，每页 10 条；发送 `删除投稿 列表 2` 查看第 2 页。 |
| 删除指定投稿 | 白名单用户发送 `删除投稿 <完整ID>`，例如 `删除投稿 q_1720000000000_ab12cd34`。只删除精确匹配的一条，成功后回复该 ID；不存在或已经删除会提示刷新列表。 |

- 输入只忽略首尾空白，`/语录`、`来条语录`、`语录 其他文字`、`摆酒席 更多` 不触发；无需 @、斜杠或管理员权限。QQ 回复自动附带的 @ 可用于投稿，其他操作不接受附带 @。删除命令的参数用空白分隔。
- 只保存被回复的原消息，保留文字空白及消息段顺序，不把“投稿”本身存入语录。
- 同一平台／机器人／会话中的同一原消息只收录一次；重复投稿仍回复 `投稿收到了～`。不同来源的同文消息各算一条。
- 所有群聊和私聊共享随机池。多段媒体仍是一条投稿，不会因拆分发送而增加抽样权重。
- 摆酒席的菜数在 `6～min(9, 投稿总数)` 中随机选择，再按投稿记录无放回抽样。同一桌不会出现同一个投稿 ID；不同来源的同文投稿仍各算一条。少于 6 条时提示当前数量和最低要求，不重复凑数。各次摆酒席之间可以抽到同一条。
- 摆酒席保留每条投稿的原消息段；纯文字菜品合成多行消息，图文按顺序呈现，语音、视频、文件和聊天记录按平台要求单独发送，菜品标签位于内容前方。
- 删除白名单默认为空，任何用户（包括管理员）均无权查看删除列表或删除，除非其 QQ 号已加入白名单。删除权限覆盖全局投稿池，不受当前群或投稿人限制；每次操作都重新检查白名单。只支持完整 ID，不接受序号、模糊匹配或批量删除；单独发送 ID 不触发删除。
- 删除后该记录立即退出语录和酒席抽样池，重启后仍保持删除。其他记录共用的媒体保留，仅清理被删记录独占的媒体；原聊天消息不受影响。删除后同一原消息可以重新投稿。
- 命中上述命令后停止事件传播，包括失败、无权限和空库，避免本次消息继续触发 LLM；忽略机器人自身事件。

## 支持与完整性

支持文字、图片（含 GIF 原文件）、QQ 表情、@／@全体成员、语音、视频、文件，以及最多三层的合并转发。普通消息和转发节点均使用完整消息段模型。

文字直接发送；图文按原顺序发送；语音、视频、文件及合并转发按平台要求分批、顺序发送。语录通过 OneBot 接口发送，保留纯空白文字段，且不会在 @ 后额外插入空格；媒体使用 AstrBot 组件转换。合并转发恢复为聊天记录，保留作者与时间。同一转发节点同时含文字／媒体和内层转发时，回放为同作者、同时间的相邻节点，保留所有内容和顺序，避免 NapCat 的嵌套节点分支丢弃相邻文字。

未知类型（如 JSON 卡片、位置等）、无法获取的引用或转发、下载失败／超时、超限、图片内容无效以及磁盘写入失败，均使整条投稿失败并说明原因。不会跳过消息段、保存占位符或错误确认成功。引用原文自身包含不支持的消息段时，同样整条失败。

回放前检查整条投稿的资源，摆酒席则在发送任何内容前检查和序列化全部选中的投稿；资源缺失时提示失败。回放与删除使用同一会话锁，正在回放的媒体不会被并发删除；抽样后已经删除的记录会使本次回放失败并提示重新抽取。实际发送仍可能被 QQ／NapCat 拒绝；分批发送中途被平台拒绝时，已经发送的批次无法撤回，该情况不会修改存档。

## 配置

在 AstrBot 的插件配置页调整。媒体限制均为正整数，MiB 为 `1024 × 1024` 字节。白名单为用户 ID 列表，推荐将 QQ 号写为字符串。

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `delete_whitelist` | `[]` | 可查看和删除全局投稿的 QQ 用户 ID，例如 `["123456789", "987654321"]`。空列表表示禁用删除。 |
| `download_timeout_seconds` | 20 秒 | 每个媒体获取（含接口解析和下载）的总超时；原消息及每次转发读取也使用此超时。 |
| `max_file_size_mb` | 50 MiB | 单个媒体大小上限，按响应头、已知大小及实际读取字节检查。 |
| `max_submission_size_mb` | 100 MiB | 单条投稿中所有媒体的合计上限，包含内层转发；相同媒体重复出现也累计。 |

## 数据与备份

数据使用独立目录 `data/plugin_data/astrbot_plugin_submit_quotes/`（优先通过 AstrBot `StarTools.get_data_dir` 定位）。保持上游按会话分目录的布局：

```text
astrbot_plugin_submit_quotes/
└── groups/
    └── <平台与机器人标识>_<群号或private_用户号>/
        ├── quotes.json
        ├── images/
        └── media/
```

先完整解析、下载和校验所有内容，再在会话锁内二次去重、写入媒体和提交快照。`quotes.json` 的 schema 版本为 4，同时包含语录、图片索引和媒体索引，通过同目录临时文件及原子替换一起提交。提交失败会清理本次新增资源，保留旧快照；不会覆盖损坏的数据。重启后直接从磁盘恢复，不依赖内存缓存。

删除同样先原子提交记录与资源索引的更新，再清理独占媒体文件；快照写入失败时原记录与文件均保留，不会回复删除成功。如果提交成功后的文件清理失败，会记录日志，删除结果仍然有效，可能留下不再参与回放的孤立文件。v1.1.0 直接沿用已有 schema 4 数据，无需迁移。

备份时复制整个插件数据目录。此适配版本使用独立目录和新快照，不会自动迁移上游插件的数据。进程被强制终止或机器断电可能留下未被快照引用的媒体文件，但不会将尚未提交的记录加入随机池。

## 验证

从包含本插件目录的根目录运行：

```bash
python -m pip install -r astrbot_plugin_submit_quotes/requirements.txt
python -m unittest discover -s astrbot_plugin_submit_quotes/tests -v
```

自动测试使用模拟 AstrBot 组件／事件、OneBot API、HTTP 传输和临时磁盘，覆盖支持类型与顺序、三层转发、超限／超时／未知类型、写入回滚、精确触发、自身事件过滤、跨群和私聊共享、并发去重与重启恢复，以及删除权限／分页／媒体清理和摆酒席的数量、无放回抽样、格式与全部菜品预检。

当前本地未安装 AstrBot，且没有 QQ／NapCat 运行实例。这些测试验证插件逻辑和预期接口，不代表真实平台收发验证。安装后应联调文字、图文、语音、视频、文件和三层转发，确认平台媒体路径／回调配置及聊天记录显示。
